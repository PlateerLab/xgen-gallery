CTA 운영 가이드 — Plateer Labs

사이트의 모든 CTA(상담·소개서·구독·발행알림)가 어떻게 접수되고, 어디에 저장되며, 누구에게 어떤 주소로 발송되는지 한 문서로 정리합니다

방문자 폼→Next.js API→구글시트 기록+xgen 메일 발송

핵심 원칙 3가지
① 모든 CTA 메일은 xgen@plateer.com에서 발송(Office 365 SMTP).
② 메일 발송은 앱(웹사이트)이 전담, 구글시트 기록은 Apps Script가 전담 — 역할을 분리해 중복 발송이 없다.
③ 발송 실패해도 접수(시트 기록)는 남고, 폼 응답은 즉시 반환된다(백그라운드 처리).

2. 동작 원리 (왜 이렇게 나눴나)

plateer.com은 Microsoft 365 메일이라, xgen@plateer.com은 O365 SMTP 계정입니다. 구글 Apps Script의 MailApp은 이 주소를 발신자로 쓸 수 없어(구조적 한계) 예전엔 소유 계정(chat2plex)으로 나갔습니다. 그래서 실제 메일 발송은 웹앱이 O365 SMTP(nodemailer)로 직접 처리하고, Apps Script는 구글시트 기록·구독 관리만 맡도록 분리했습니다.

  • 발송 = 앱 — frontend/src/lib/mailer.ts (smtp.office365.com:587 STARTTLS, 발신 xgen@plateer.com)
  • 기록 = Apps Script — docs/lead-webhook.gs (리드관리 스프레드시트에 바인딩, 탭: leads/brochure/subscribers)
  • 두 경로가 겹치지 않으므로 메일 1통 · 기록 1행이 보장됩니다.

발신 표시이름: 앱은 "Plateer Labs" <xgen@plateer.com>로 보내지만, O365가 사서함 계정 표시이름("AI솔루션연구소")으로 덮어써 그렇게 보일 수 있습니다. "Plateer Labs"로 통일하려면 M365 관리센터 → xgen@plateer.com → 표시 이름 변경이 필요합니다.

4. CTA별 상세 · 수신자

4-1. 상담 신청 xgen 발신

메일발신수신회신(Reply-To)
신청자 접수확인xgen@plateer.com신청자 본인(폼 이메일)xgen@plateer.com
내부 팀 알림xgen@plateer.comchat2plex@gmail.com + xgen@plateer.com신청자 이메일(바로 회신용)

leads 탭 기록 항목: 수신시각 · 문의 유형 · 레퍼러 페이지 · 성함 · 이메일 · 연락처 · 회사 · 부서 · 직급 · 방문경로 · 상담 내용 · 개인정보취급방침 동의 · 개인정보 수집·이용 동의 · 마케팅 수신 동의. 문의 유형: 제품 데모 요청 / XGEN 15일 무료 체험 신청 / PoC·기술 상담 / 도입·견적 문의 / 기타.

레퍼러 페이지 = 상담 폼 작성 직전에 보던 페이지 주소. 모달이면 그 페이지, /contact 단독 진입이면 유입 이전 페이지, 직접 방문이면 /contact?from=…로 폴백 기록됩니다.

4-2. 소개서 다운로드 xgen 발신

메일발신수신회신
요청자 다운로드 링크xgen@plateer.com요청자 본인xgen@plateer.com
내부 접수 알림xgen@plateer.comswan@plateer.com + xgen@plateer.com요청자 이메일

소개서 종류는 폼의 asset 값으로 구분합니다(카탈로그 frontend/src/lib/brochures.ts). 현재 XGEN(발행), AI Code Assistant(준비 중). 새 종류는 PDF를 /public/downloads에 올리고 카탈로그·lead-webhook.gs BROCHURE_TYPES에 한 줄씩 추가. 첨부가 아니라 다운로드 링크로 보냅니다.

4-3. 뉴스레터·블로그 구독/해지 메일 없음

  • 구독 = subscribed: "Y", 해지 = "N". subscribers 탭에서 이메일+구분(kind) 기준 upsert(재구독·해지 시 갱신).
  • 구분(kind): blog(새 글 알림) / newsletter(새 호 알림) — 서로 독립(뉴스레터를 해지해도 블로그 구독은 유지).
  • 해지 링크: /unsubscribe?kind=…&email=… (발행 알림 메일 하단에 수신자별로 삽입됨).

4-4. 발행 알림(자동) xgen 발신

새 블로그 글 또는 뉴스레터 호가 main에 올라오면 GitHub Action이 감지 → 앱이 구독자에게 요약 메일을 보냅니다.

발행 감지(Action)→/api/content-notify→구독자 명단 조회(Apps Script)→xgen 발송
  • 토큰 인증: Action → 앱 라우트 요청에 BLOG_NOTIFY_TOKEN이 맞아야 실행(공개 라우트 남용 방지).
  • 구독자 명단은 구글시트에만 있으므로 앱이 Apps Script의 subscribers 조회 액션으로 구독중(Y)만 가져와 발송 — 해지자(N)는 자동 제외.
  • 발신 xgen@plateer.com · 수신 구독중 구독자 · 회신 xgen · 하단 개인별 해지 링크.

5. 데이터 저장 (구글시트)

한 스프레드시트(리드관리)에 탭으로 분리. 헤더는 스크립트가 자동 보정하며, 동시 제출은 스크립트 락으로 직렬화해 행 유실을 방지합니다.

탭용도주요 컬럼
leads상담 신청수신시각·문의 유형·레퍼러·성함·이메일·연락처·회사·부서·직급·방문경로·상담 내용·동의(3)
brochure소개서 다운로드수신시각·소개서(종류)·성함·이메일·연락처·회사·부서·직급·방문경로·동의(3)
subscribers구독 상태수신시각·구분(blog/newsletter)·이메일·구독여부(Y/N)

6. 환경변수 · 시크릿

운영(go244)의 .env는 배포 시 GitHub 시크릿에서 자동 시딩됩니다. 값 자체는 절대 코드/문서에 넣지 않습니다.

키용도기본값 / 비고
SMTP_USER발신 계정xgen@plateer.com
SMTP_PASSO365 SMTP 인증 비밀번호 시크릿미설정 시 앱 발송 조용히 생략(도먼트)
SMTP_HOST/SMTP_PORTSMTP 서버smtp.office365.com / 587(STARTTLS)
MAIL_CONTACT_TO상담 내부알림 수신처chat2plex@gmail.com, xgen@plateer.com
MAIL_BROCHURE_TO소개서 내부알림 수신처swan@plateer.com, xgen@plateer.com
DEMO_WEBHOOK_URLApps Script /exec (시트·구독)상담·소개서·구독·명단조회 공용
NEWSLETTER_WEBHOOK_URL/BROCHURE_WEBHOOK_URL전용 웹훅(선택)없으면 DEMO_WEBHOOK_URL로 폴백
BLOG_NOTIFY_TOKEN발행 알림 인증 시크릿3곳 동일값 필수 → 아래 참조

⚠️ BLOG_NOTIFY_TOKEN은 세 곳이 반드시 같아야 발행 알림이 동작합니다:
① GitHub 저장소 시크릿(Action) · ② go244 .env(앱 검증·Apps Script 호출) · ③ Apps Script 스크립트 속성. 값을 바꾸면 세 곳을 함께 갱신하세요. (불일치 시 앱 라우트가 401 반환 → 발송 안 함 = 안전측 실패)

7. 배포 · 반영 방법

대상반영 방법
앱(웹사이트)main에 push → GitHub Action "Deploy to go244"가 자동 재빌드·시크릿 시딩
Apps Script(lead-webhook.gs)Code.gs에 붙여넣기 → 배포 관리 → 편집(연필) → 새 버전 → 배포 (URL 유지)

Apps Script 함정: Ctrl+S(저장) ≠ 배포입니다. "새 배포"를 만들면 /exec URL이 바뀌어 앱의 DEMO_WEBHOOK_URL과 어긋납니다 — 반드시 기존 배포를 "편집 → 새 버전"으로 올리세요.

8. 운영 체크리스트

  • 폼 제출 시 시트에 1행 쌓이고, 확인 메일·내부알림이 각 1통(중복 없음) 오는가
  • 모든 CTA 메일 발신이 xgen@plateer.com인가(chat2plex 아님)
  • 상담 내부알림이 chat2plex@gmail.com(gmail!) + xgen로 가는가
  • 소개서 내부알림이 swan + xgen로 가는가
  • 구독/해지가 subscribers 탭 Y/N로 갱신되는가
  • 새 글/새 호 발행 후 구독자에게 요약 메일이 xgen에서 1통 가는가(해지자 제외)
  • BLOG_NOTIFY_TOKEN 3곳이 동일한가

9. 문제 해결

증상원인 / 조치
메일이 아예 안 옴앱 SMTP_PASS 미설정/오류 → go244 재배포·시크릿 확인. 사서함 MFA면 앱 비밀번호 필요. M365에서 "인증된 SMTP(SMTP AUTH)" 활성화 확인
발신자가 chat2plex로 나옴예전 Apps Script(B모드) 잔재 → 최신 lead-webhook.gs로 새 버전 배포(CTA 메일 발송이 주석 처리되어 있어야 함)
같은 메일이 2통 옴앱과 Apps Script가 동시 발송 중 → Apps Script CTA 메일 발송 주석 유지 확인 후 재배포
시트에 데이터 안 쌓임DEMO_WEBHOOK_URL 확인. 새 배포로 URL이 바뀌었는지 점검(편집→새 버전으로 재배포하면 URL 유지)
발행 알림이 401BLOG_NOTIFY_TOKEN 3곳 불일치 → 동일 값으로 맞춤
한글이 깨져 보임테스트 시 셸(curl -d) 인코딩 문제 — 실제 브라우저 폼은 정상. 테스트는 UTF-8 파일로 전송
동시 제출 시 행 유실이미 스크립트 락으로 직렬화 처리됨(최신 lead-webhook.gs 배포 필요)

10. 롤백 (앱 발송 실패 시)

앱 O365 SMTP가 장애나면, Apps Script가 다시 메일을 보내도록 즉시 되돌릴 수 있습니다. lead-webhook.gs doPost의 상담·소개서 브랜치에 주석 처리된 발송 2줄을 해제하고 새 버전 배포하면 B모드(표시명 Plateer Labs + 답장 xgen)로 복구됩니다. 단, 이 경우 발신은 chat2plex 계정으로 나갑니다.
