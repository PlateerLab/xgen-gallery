아래 Vol.5 뉴스레터는 스티비 HTML 편집기에 붙여 넣도록 만든 발송용 원본입니다. 웹 미리보기 전체 소스를 복사하지 말고, 반드시 아래 버튼으로 뉴스레터 본문만 복사하세요.

스티비 도움말 열기 Outlook HTML 형식 안내 Outlook CSS 지원표

뉴스레터 제목

스티비에서 편집하는 순서

  1. 스티비용 HTML 복사를 누릅니다. 안내 영역을 제외한 실제 메일 본문만 복사됩니다.
  2. 스티비에서 새 이메일을 만들고 HTML 직접 편집 영역에 붙여 넣습니다.
  3. 제목과 프리헤더를 확인하고, 이미지가 모두 HTTPS 주소로 표시되는지 점검합니다.
  4. 데스크톱·모바일 미리보기를 확인한 뒤 Outlook 계정으로 테스트 발송합니다.
  5. 테스트 메일의 링크, 이미지 다운로드 전후 화면, 수신거부 링크를 확인한 뒤 발송합니다.

Outlook 최적화 기준

  • 레이아웃은 표 기반이며, 폭·정렬·여백·글꼴을 각 요소의 인라인 스타일로 지정했습니다.
  • 본문 폭은 700px로 고정하고 바깥 표의 align="center"로 중앙 정렬했습니다.
  • 기본 글꼴은 Pretendard, Noto Sans KR, Malgun Gothic, Arial 순서입니다. 다만 Outlook은 웹폰트를 안정적으로 불러오지 않으므로, 수신자 PC에 Pretendard가 없으면 Malgun Gothic 또는 Arial로 표시됩니다.
  • 이미지는 공개 HTTPS 주소와 명시적 너비를 사용하며, 중요한 문구를 배경 이미지 안에 넣지 않았습니다.
  • 섹션 배경색은 bgcolor와 인라인 background-color를 함께 사용했습니다.
  • JavaScript, 외부 스타일시트, 웹폰트, flex/grid 레이아웃은 실제 메일 본문에 포함하지 않았습니다.
주의: 브라우저와 Outlook은 서로 다른 렌더링 엔진을 사용하므로 픽셀 단위로 완전히 같게 보장할 수 없습니다. 이 원본은 글꼴 대체, 섹션 정렬, 표 레이아웃과 이미지 크기가 무너지지 않는 것을 우선합니다.

플래티어 AI솔루션연구소도 XGEN 개발과 산출물 작성에 XGEN을 직접 활용하려 합니다. 대화로 에이전트를 만들고 업무를 맡기는 경험을 XGEN에 구현하고 있으며, 현재는 실제 업무 활용을 위한 완성도와 품질 고도화에 집중하고 있습니다.

이를 뒷받침하는 것이 하네스입니다. 모델이 도구를 선택하고, 작업 내용을 기억하고, 오류가 나면 다시 시도하도록 돕는 실행 체계입니다. 요청을 이해하는 것만큼이나 작업 맥락을 유지하고 결과를 확인하는 과정이 중요합니다. LangChain은 같은 모델에서 하네스만 개선해 Terminal-Bench 2.0 점수를 52.8에서 66.5로 높였습니다.

재즈 피아니스트 배리 해리스의 레슨에는 이런 말이 나옵니다.

“너희는 전혀 스윙하고 있지 않아.”

음을 정확히 연주하는 것만으로는 재즈의 느낌을 살릴 수 없다는 뜻입니다. 에이전트도 좋은 모델을 연결하는 데서 끝나지 않습니다. 도구와 기억, 실행 과정이 잘 맞물려야 맡긴 일을 끝까지 해낼 수 있습니다.

기업 환경에서는 도구를 연결하는 일도 다릅니다. 인터넷에서 잘 작동하는 도구라도 폐쇄망에서는 그대로 쓰기 어렵고, 사내 데이터와 업무 절차에 맞춘 연동이 필요합니다. 오픈소스를 활용하더라도 보안과 안정성을 따로 검증해야 합니다. XGEN 하네스를 자체 개발한 이유입니다. 작업 기록과 개선 경험이 쌓일수록 더 나은 결과를 내도록 설계하고 있으며, 현재 Claude Code·Codex와 품질을 비교하고 있습니다.

사용이 편리한 것만큼 운영 과정도 확인할 수 있어야 합니다. 누가 에이전트 배포를 승인했는지, 검증한 버전이 실제로 실행되는지, 어떤 데이터에 접근했고 비용은 얼마나 들었는지 알아야 합니다. XGEN은 결재, Agent 고정, 실행 기록, 사용량 집계를 한 시스템에서 제공합니다. 사용자는 대화로 업무를 맡기고, 관리자는 승인부터 실행 이력과 비용까지 확인할 수 있도록 만드는 것입니다.

XGEN에서는 도구 실행 승인과 개인정보 검사 등에 적용을 검토할 수 있습니다. 다만 외부 입력에 포함된 가짜 승인 문구로 차단 확률이 0.76에서 0.48로 낮아진 실험도 보고됐습니다. 판단 모델을 단독 승인 수단으로 쓰지 않고, 권한·규칙 검사를 함께 적용해야 합니다. · VentureBeat · 6min

Dream-RSI: Recursive Self-Improvement through Evolving Worlds
Tong Zheng et al. · Google 외
Dream-RSI는 기존 탐색 기록으로 새로운 탐색 전략을 평가한 뒤, 개선된 전략을 실제 작업에 적용하는 연구입니다. 에이전트 모델 자체가 아닌 작업 조율 계층을 변경합니다.

논문에서는 알고리즘 설계, 수학 최적화, GPU 커널 작성에서 성능을 유지하거나 개선하면서 비용을 줄였다고 보고합니다. 기업 관점에서는 축적된 작업 기록을 재활용해 실험 비용을 줄일 가능성이 있으며, 실제 업무에서의 효과는 별도 검증이 필요합니다.

RRSI: Regularized Recursive Self-Improvement of Agent Harnesses
Peng Xia et al. · Google Cloud AI Research 외
RRSI는 에이전트가 지시문·도구·기억 관리 등을 스스로 개선할 때 특정 과제에만 맞춰지는 문제를 줄이는 연구입니다. 변경 범위를 제한하고, 다른 과제에서도 유효한지 검증하며, 효과가 낮거나 비용이 큰 변경을 제거합니다.
