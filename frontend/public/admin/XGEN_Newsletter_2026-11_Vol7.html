XGEN 11월 업데이트
AI Agent의 확산,
이제는 연결과 운영까지 관리해야 할 때
AI Agent를 쓰는 업무가 늘어나면서, 에이전트와 연결 도구를 관리하는 일도 함께 중요해지고 있습니다. 이번 호에서는 이를 위한 XGEN의 11월 업데이트를 소개합니다.
AI Agent가 질문에 답하는 데서 나아가 실제 업무를 처리하려면 메일, 문서, 사내 시스템 같은 도구와 연결되어야 합니다. MCP(Model Context Protocol)는 이 연결에 쓰이는 표준 프로토콜입니다. 연결된 에이전트와 도구가 늘어날수록 운영 담당자가 파악해야 할 것도 많아집니다. 어떤 에이전트가 어떤 도구를 쓰는지, 누가 얼마나 사용하는지, 특정 서버를 내리면 어떤 업무가 멈추는지입니다. Microsoft도 11월 17일 Ignite에서 자사 에이전트 관리 제품에 MCP 서버 관리 기능을 추가했습니다.

XGEN은 11월 업데이트에서 MCP 관리 기능을 [MCP 서버 관리]와 [MCP 카탈로그 관리] 두 화면으로 나눠 새로 구성했습니다. 모든 MCP 호출을 한곳에서 기록해 사용량과 오류 현황을 확인할 수 있고, 같은 MCP 서버도 사용자마다 각자의 계정으로 연결해 쓸 수 있습니다. 이 기능은 11월 18일 검증 환경에 반영했으며, 다음 운영 릴리즈에 포함될 예정입니다.

앞서 11월 12일 운영 릴리즈에는 10월에 검증 환경에서 소개한 기능과, 지난 호에서 남은 과제로 안내한 보안 개선 3건을 반영했습니다. 이 밖에 에이전트가 기억한 내용을 사용자가 직접 확인하고 고칠 수 있는 기록 메모리, 화면이 바뀌면 매뉴얼을 자동으로 갱신하는 매뉴얼 업데이터 소식도 함께 전합니다.

기본 제공 MCP 카탈로그
호출 기록과 대시보드. 지금까지는 MCP 도구가 언제, 누구의 요청으로 호출됐는지 기록이 남지 않았습니다. 이제 에이전트 실행, 도구 연결, 웹 자동화 등 XGEN 서버를 거치는 MCP 호출을 한 지점에서 기록합니다. 호출마다 사용자, 에이전트, 도구, 성공 여부와 함께 호출 위치(캔버스·배포 웹·배포 API·예약 실행·서브 에이전트)가 남고, 90일 동안 조회하거나 엑셀로 내려받을 수 있습니다. 대시보드에서는 24시간 호출 수, 오류율, 응답 시간(p95), 많이 쓰는 도구·사용자·에이전트 순위를 보고, 순위를 누르면 해당 호출 기록으로 바로 이동합니다.
기록은 호출을 늦추지 않도록 백그라운드에서 저장하며, 기록 저장에 실패해도 호출은 그대로 진행됩니다. 도구에 넘긴 값과 결과, 개인 변수 값은 저장하지 않습니다.
사용처 확인. 서버 상세의 [사용처]에서 이 MCP 서버를 쓰는 에이전트와 노드, 배포 상태를 확인합니다. 서버 설정을 바꾸거나 내리기 전에 영향을 받는 에이전트를 먼저 알 수 있습니다. 설정을 바꿀 때는 [재시작]을 쓰면 서버 ID가 그대로 유지돼, 캔버스와 배포된 에이전트를 다시 연결하지 않아도 됩니다.
공용 변수와 개인 변수. 지금까지 서버에서 실행한 MCP는 하나의 프로세스를 모든 사용자가 같은 설정으로 함께 썼습니다. 이제 변수를 둘로 나눕니다. 모두가 같이 쓰는 값은 공용 변수로 한 번 정하고, 사람마다 다른 값(예: 각자의 Google 계정)은 개인 변수로 선언합니다. 개인 변수 조합마다 별도 프로세스를 실행하므로 같은 MCP 서버를 사용자마다 자기 계정으로 쓸 수 있고, MCP 서버 코드는 고칠 필요가 없습니다.
MCP 카탈로그. 사용자 PC에 설치해 쓰는 MCP는 데스크톱 앱 DexOn이 맡습니다. 관리자가 카탈로그에 설치 방법과 변수를 정의해 두면, 사용자는 변수만 입력하고 DexOn이 설치부터 에이전트 연결까지 처리합니다. GitHub, Notion, Jira·Confluence, 브라우저 자동화, 파일 시스템 등 14종을 기본으로 담았고, 모두 버전을 고정했습니다. 버전을 ‘최신’으로 지정하거나 비밀값이 평문으로 남는 위치에 들어간 정의는 저장 단계에서 막습니다.
[관리 > MCP 관리 > MCP 카탈로그 관리] 기본 제공 MCP 14종입니다. 항목마다 실행 방식, 변수 수, 설치 현황이 보입니다. (개발 환경)
현재 검증 환경(stage)에 반영돼 있으며, 다음 운영 릴리즈에 포함할 예정입니다.
보안 후속 조치
지난 호의 남은 과제 3건, 운영 환경에 반영했습니다
지난 호에서 ARTEX 점검 후 조치 중이라고 말씀드린 3건을 11월 12일 운영 릴리즈에 포함했습니다.
게스트 계정 남용 방지. 게스트 가입은 같은 주소에서 시간당 10회, 하루 200회로 제한하고, 게스트 역할에는 하루 10만 토큰 한도를 둡니다. 게스트 여부는 로그인 정보가 아니라 DB에 저장된 역할로 판정합니다.
허용한 주소에서만 호출. 모든 출처의 요청을 허용하던 CORS 설정을, 허용한 주소만 받는 목록 방식으로 바꿨습니다.
로그인 토큰 재사용 탐지. 갱신 토큰을 한 번 쓰면 새 토큰으로 바꾸고, 이미 쓴 토큰이 다시 들어오면 탐지하는 기능을 추가했습니다. 기본값은 꺼져 있으며, 고객 환경에 맞춰 켤 수 있습니다.
이와 함께 설정 변경 로그에 비밀값 원문이 남지 않도록 했고, 보안 설정 8가지를 [시스템 설정 > 앱]에서 관리자가 직접 조정할 수 있게 했습니다. 조치 후 재검증은 이어서 진행하고, 결과는 다음 호에서 공유하겠습니다.
11월 XGEN 주요 업데이트
11월의 주요 기능과 개선 사항입니다. main은 11월 12일 운영 릴리즈에 포함된 기능이고, stage는 11월 18일 검증 환경에 반영돼 다음 운영 릴리즈를 기다리는 기능, dev는 개발 환경에서 운영 중인 기능입니다. 10월에 소개한 기능도 이번 운영 릴리즈에 함께 반영했으며, Geny는 품질 검증을 마친 뒤 운영 환경에서 켤 예정입니다.
로그 원본 · 암호화해 보관하고, 사유를 남겨야 열립니다
 신규main
서비스별 원본 로그를 날짜별 파일로 암호화해 30일 동안 보관합니다. 관리자가 로그를 조회하거나 내려받으려면 사유를 입력해야 하고, 사유와 열람 기록은 [열람 이력]에 남습니다. 복호화한 화면은 30분 동안만 열리며, 전체 검색과 앞뒤 구간 이동을 지원합니다.

장애나 보안 사고를 조사할 때 원본 로그가 필요하지만, 원본에는 민감한 내용이 섞이기 쉽습니다. 그래서 누가, 왜 열었는지 기록이 남도록 했습니다. 다만 내려받은 파일은 이후 사용 내역을 추적할 수 없으므로, 다운로드 권한은 꼭 필요한 관리자에게만 주는 것을 권장합니다.
[관리 > 시스템 상태 > 로그 조회 > 로그 원본] 서비스별로 하루 단위 암호화 파일이 쌓입니다. 조회와 다운로드 모두 사유를 입력해야 합니다. (개발 환경)
Agent 자원 관리 · 에이전트마다 저장 공간 한도를 둡니다
 신규main
에이전트마다 작업 공간과 샌드박스 디스크의 사용량을 보여 주고 한도를 적용합니다. 샌드박스는 기본 20GiB, 사용자가 늘릴 수 있는 최대치는 60GiB이며, 한도를 넘으면 업로드를 막고 안내합니다. 용량을 더 늘려야 하면 결재를 거쳐 요청합니다.

관리자는 [관리 > Agent 운영 > Agent 자원 관리]에서 전체 사용량과 한도에 가까운 에이전트를 한눈에 확인하고, 오래 쓰지 않는 공간을 정리할 수 있습니다.
기록 메모리 · 에이전트가 기억한 내용을 보고 고칩니다
 신규stage
에이전트가 대화에서 알게 된 내용을 규칙, 사실, 상태, 결정, 절차 다섯 가지로 나눠 기록합니다. ‘보고서는 표로 정리한다’는 규칙이고, ‘이번 분기 담당자는 누구다’는 사실입니다.

사용자는 에이전트의 [메모리] 탭에서 이 기록을 직접 보고 고칠 수 있습니다. 고칠 때마다 새 버전으로 저장되므로, 잘못 고쳤으면 이전 버전으로 되돌리면 됩니다. 에이전트가 무엇을 기억하고 있는지 사람이 확인할 수 있어야 믿고 맡길 수 있다는 판단에서 만든 기능입니다. 아래 ‘읽을거리’에서 에이전트 기억의 구성 요소를 다룬 글을 함께 소개합니다.
서브 에이전트 · 만든 에이전트를 다른 에이전트 안에서 씁니다
 신규stage
Agent Geny가 사용자의 계정으로 에이전트를 직접 만들고, 이미 있는 에이전트를 서브 에이전트로 불러 쓸 수 있습니다. 예를 들어 ‘자료 조사 에이전트’와 ‘보고서 작성 에이전트’를 따로 만든 뒤, 둘을 순서대로 부르는 상위 에이전트를 구성하는 방식입니다.

캔버스에서는 서브 에이전트 노드를 펼쳐 그 안의 워크플로를 두 단계까지 바로 확인할 수 있습니다. Geny가 하루에 만들 수 있는 에이전트는 사용자당 20개로 제한했습니다.
매뉴얼 업데이터 · 화면이 바뀌면 매뉴얼이 따라 바뀝니다
 신규dev
XGEN 화면 85개에는 각각 ‘화면 계약’이 있습니다. 화면에 어떤 버튼과 입력칸이 있고 누구에게 언제 보이는지를 적은 파일입니다. 개발자가 화면 코드를 반영하면 봇이 계약 파일을 함께 고치고, 판단이 필요한 부분만 후속 MR로 개발자에게 넘겨 검토를 받습니다.

11월 17일부터는 매일 오전 8시에 매뉴얼 업데이터가 실행됩니다. 바뀐 계약을 보고 영향을 받는 챕터를 찾아 화면을 다시 캡처하고, 고쳐야 할 문장만 XGEN에 연결한 Claude가 다시 작성합니다. 캡처에 찍힌 이름, 연락처 같은 정보는 가린 뒤 올립니다. 11월 16일부터 19일까지 챕터 38개를 고치고 화면 이미지와 GIF 438장을 새로 찍었습니다. 지금은 개발 환경 매뉴얼에 적용돼 있으며, 하반기에 합류한 신입 두 명이 만들었습니다.
XGEN 앱 안의 매뉴얼에서 연 [관리 설정 개요] 챕터입니다. 본문 캡처는 업데이터가 화면을 직접 찍어 넣은 것이며, 이름 등 개인 정보는 회색 막대로 가렸습니다. (개발 환경)

DevStudio · 대화로 만든 앱을 서버에 올려 운영
 개발중
대화로 만든 앱을 XGEN 서버에 배포하고 운영하는 기능입니다. 11월에는 HTTPS 인증서 적용, 새 버전을 띄운 뒤 트래픽을 넘기는 블루그린 배포, 새 버전이 30초 안에 멈추면 이전 버전으로 자동으로 되돌리는 기능을 넣었습니다. 배포가 실패하면 원인을 유형별로 분류해 보여 주고, 배포 전에는 결재를 거칩니다. 화면 없이 API만 제공하는 앱 유형도 추가했습니다.

 품질 검증 중

XGEN으로 만든 사내 서비스
XGEN 위에서 만든 사내 서비스를 소개합니다.
플래티어 사내 AI 비서
헤이플 · 회의 녹음부터 회의록 공유까지 Teams 안에서
헤이플은 XGEN 에이전트를 Teams에 연결한 플래티어 사내 AI 비서입니다. 11월 4일 운영 환경으로 전환했으며, Teams에서 봇과 대화하거나 [헤이플]·[Voice Note] 탭을 열어 바로 쓸 수 있습니다.

Voice Note는 회의를 녹음하거나 녹음 파일을 올리면 받아쓰기와 AI 노트를 함께 만들어 줍니다. 노트는 폴더로 정리하고, Word 파일로 OneDrive나 SharePoint에 저장하거나 메일 초안으로 바로 보낼 수 있습니다. 여러 기기에서 같은 노트를 이어서 볼 수 있고, 노트를 만들기 전에 예상 토큰 사용량도 보여 줍니다. 지금은 Teams 밖에서도 쓸 수 있는 웹 서비스를 준비하고 있습니다.
Teams 안에서 연 헤이플 앱입니다. 회사 규정을 바탕으로 연봉 인상 방법을 묻는 질문에 답하고 있습니다. 이름은 가렸습니다.

에이전트를 운영하는 방식이 바뀌고 있습니다
01 Microsoft · Agent 365에서 MCP 서버까지 관리합니다 ↗
Microsoft는 11월 17일 Ignite에서 에이전트 관리 제품 Agent 365의 새 기능을 발표했습니다. 관리자가 Copilot의 플러그인과 스킬을 관리하는 화면에 MCP 서버를 함께 올리고, MCP 서버를 차단하기 전에 어떤 에이전트와 플러그인이 그 서버를 쓰는지 먼저 보여 줍니다. 직원 PC에서 돌아가는 로컬 에이전트 60여 종과 그 에이전트가 쓰는 MCP 서버를 탐지하는 기능도 미리보기로 공개했습니다.

MCP 서버가 기업의 관리 대상으로 들어오고 있습니다. 서버를 내리기 전에 영향을 받는 에이전트를 먼저 보여 준다는 점은 이번 호에서 소개한 XGEN MCP 서버 관리의 [사용처]와 같은 접근입니다. · Microsoft Tech Community · 3min
02 GitHub · 저장소 관리를 맡는 에이전트 워크플로 정식 출시 ↗
GitHub는 10월 28일 Agentic Workflows를 정식 출시했습니다. 마크다운으로 작업을 적으면 GitHub Actions 워크플로로 바뀌어, 이슈 정리나 문서 갱신 같은 저장소 관리 작업을 에이전트가 정기적으로 수행합니다. 에이전트는 기본적으로 읽기 권한만 갖고, 격리된 컨테이너와 전용 방화벽 안에서 실행됩니다. 함께 소개된 고객 사례에서는 한 팀의 커밋 91%를 AI가 작성한다고 밝혔습니다. 다만 고객이 자체적으로 밝힌 수치입니다.

반복되는 업무를 에이전트에게 맡길 때 가장 먼저 정해야 하는 것은 권한의 범위입니다. 기본은 읽기 전용, 쓰기는 정해진 경로로만 허용하는 방식은 XGEN이 설계하고 있는 도구 권한과 같은 방향입니다. · GitHub · 2min
03 Google · 출시한 제품을 계속 고치는 에이전트 ↗
Google Labs는 11월 18일 Stitch Loop를 공개했습니다. 코드 저장소와 실제 서비스 지표에 연결된 에이전트가 개선점을 제안하고, 해결책을 만들어 GitHub PR로 올린 뒤 사람의 승인을 받고, 결과를 돌아보는 과정을 반복합니다. 보안, 응답 속도, 접근성 세 가지 루프를 기본으로 제공하고 사용자가 직접 루프를 정의할 수도 있습니다. 아직 실험 단계로, 대기자 신청을 받고 있습니다.

에이전트의 일이 ‘만들기’에서 ‘출시 후 계속 고치기’로 넓어지고 있습니다. 바꾼 것은 사람이 승인하고 기록은 저장소에 남긴다는 구조는 이번 호의 매뉴얼 업데이터와 같습니다. · Google · 3min

문서·기억·검증, 에이전트에게 유지보수를 맡기는 설계
01 Mintlify · 스스로 갱신되는 문서의 구조 ↗
개발 문서 서비스 Mintlify는 10월 30일 자동 문서 갱신 시스템을 다시 설계한 과정을 공개했습니다. 사이트마다 하루 한 번 배경 에이전트가 고칠 곳을 찾고, 실행 에이전트가 문서 PR을 만듭니다. 에이전트의 기억은 정해진 형식의 JSON으로 git에 저장합니다. 사내 문서에서 PR 채택률이 70%에서 90%로 올랐다고 밝혔으며, 이는 자체 측정치입니다.

하루 한 번 돌고, 기억을 저장소에 남기고, 결과를 MR로 낸다는 점에서 이번 호의 매뉴얼 업데이터와 거의 같은 구조입니다. · Mintlify · 7min
02 Anthropic · 에이전트 기억은 무엇으로 이루어지나 ↗
Anthropic은 11월 6일 에이전트 기억의 구성 요소를 정리한 글을 공개했습니다. 작업 기록을 그대로 쌓아 두기보다, 작업이 없는 시간에 기록을 다시 읽고 고친 노트와 위키로 정리하는 ‘드리밍’ 과정을 제안합니다. 약 35만 개 파일로 이뤄진 문서 묶음에서는 이 정리를 128회 반복하자 점수가 13%에서 48%로 올랐습니다. 모두 Anthropic 자체 평가 결과입니다.

기억은 쌓는 것보다 정리하고 고치는 일이 더 중요하다는 결론입니다. XGEN의 기록 메모리가 사람이 직접 기록을 고치고 되돌릴 수 있게 한 것도 같은 이유입니다. · Anthropic · 13min
03 Claude Code 팀 · 에이전트에게 검증 수단부터 쥐여 줍니다 ↗
Claude Code 팀은 11월 16일 코드의 약 90%를 Claude가 작성하고 검토하는 환경에서 결과를 어떻게 검증하는지 소개했습니다. 핵심은 에이전트가 스스로 결과를 확인할 수 있도록 종단 테스트, 속성 기반 테스트, 이전 버전과의 비교 테스트를 갖춰 두는 것입니다. 별도의 채점 기준을 두면 과제 성공률이 최대 10%p 올랐고, 같은 검사를 세 번 고쳐도 실패하면 에이전트가 멈추고 사람을 부릅니다.

에이전트에게 일을 많이 맡길수록 사람이 하나하나 보는 대신 검증 장치를 먼저 만들어야 합니다. 매뉴얼 업데이터가 자동 반영 전에 품질 검사를 거치게 한 것도 이 원칙을 따른 것입니다. · claude.dev · 10min

문서와 실제 사이의 틈을 찾는 에이전트
11월에 공개된 연구로, 이번 호의 매뉴얼 자동 최신화와 같은 문제를 다룹니다. 문서가 실제와 어긋난 곳을 에이전트가 찾아낼 수 있을까요?
arXiv 2611.23142
Mind the Gap · 문서 유지보수를 맡은 멀티 에이전트, 실제 운영 기록
Lorenzo Masoero · Amazon · IAAI-27 채택
사내 서비스의 문의 대응에서 같은 질문이 반복되는 이유는 대개 문서에 빠진 내용이 있기 때문입니다. 이 연구는 A/B 테스트 분석 서비스의 실제 문의 창구에 멀티 에이전트를 붙여, 문의에 답하면서 문서에 빠지거나 틀린 부분을 찾아내도록 했습니다.

운영에 영향을 주지 않는 섀도 모드로 43일 동안 문의 499건을 처리했고, 문서의 빈틈 92곳을 찾아냈습니다. 에이전트가 쓴 답변에서 확인 가능한 주장 302개 중 81.1%가 사실과 맞았고, 길이가 비슷한 답변끼리 비교했을 때 평가자는 70.5%의 경우 에이전트의 답을 더 낫다고 골랐습니다. 문서가 실제와 어긋나는 문제를 사람의 기억이 아니라 시스템이 계속 찾아내도록 한다는 점에서, 이번 호의 매뉴얼 업데이터와 같은 방향의 연구입니다.
