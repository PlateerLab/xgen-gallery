생성형 AI에게 "이 Excel 파일을 분석해서 보고서로 정리해줘"라고 요청했다고 생각해 보겠습니다.

하지만 실제 업무에서는 그다음 과정이 남아 있습니다.

파일을 찾아 업로드하고, 결과를 다시 다운로드하고, Excel이나 PowerPoint를 열어 수정하고, 필요한 자료가 있으면 브라우저에서 검색하고, 완성된 파일을 업무 폴더에 저장해야 합니다.

결국 **AI가 동작하는 환경과 사람이 실제 업무를 수행하는 환경이 분리되어 있기 때문**입니다.

XGEN DeX는 이 간극을 연결하기 위해 만들어지고 있습니다.

## XGEN DeX란?

XGEN DeX는 **XGEN에서 생성·관리되는 AI Agent와 사용자의 실제 PC 업무환경을 연결하는 Desktop Interface**입니다.

XGEN에서 업무용 Agent를 만들고 관리한다면, DeX는 해당 Agent가 사용자의 PC 업무환경에서 실제 업무를 수행할 수 있도록 연결합니다.

단순히 PC에서 XGEN 채팅을 사용할 수 있게 만드는 데스크톱 앱과는 목적이 다릅니다.

DeX를 통해 Agent는 허용된 범위에서 로컬 파일과 애플리케이션을 활용하거나 브라우저를 사용하고, 필요한 Tool과 Skill을 실행하여 실제 결과물을 만들어낼 수 있습니다.

즉,

**XGEN = Agent를 만들고 관리하는 곳**

이라면,

**XGEN DeX = Agent가 실제 업무를 수행할 수 있도록 사용자 환경과 연결하는 곳**

이라고 이해하면 쉽습니다.

이름은 **XGEN DeX**(Desktop Experience)이고, 하는 일은 서버의 Agent와 사용자의 로컬 업무환경을 연결하는 **실행 인터페이스**입니다. 그래서 설치 파일과 저장소 이름에는 `xgen-connector`가 그대로 남아 있습니다.

## 왜 DeX가 필요할까요?

기업의 업무는 하나의 AI 채팅창 안에서 끝나지 않습니다.

직원들은 업무를 처리하면서 수많은 환경을 오갑니다.

**파일 → Excel → 브라우저 → 사내 시스템 → PowerPoint → 업무 폴더**

AI가 실제 업무를 수행하려면 이러한 업무환경과 자연스럽게 연결될 수 있어야 합니다.

그래서 XGEN DeX가 지향하는 AI 활용 방식은 기존의

**질문 → 답변**

에서 한 단계 더 나아갑니다.

**업무 요청 → 필요한 도구 선택 → 실행 → 결과물 생성**

예를 들어 "지난달 데이터를 분석해줘"에서 끝나는 것이 아니라,

> "지난달 실적 파일을 확인해서 주요 변화를 분석하고 결과 파일을 만들어줘."

와 같이 **결과물까지 완성하는 업무 단위**로 Agent에게 요청할 수 있는 환경을 만드는 것입니다.

## 어떻게 사용하나요?

DeX의 사용 방식은 일반적인 업무용 AI보다 오히려 단순하게 만드는 것을 목표로 합니다.

큰 흐름은 여섯 단계입니다.

| 단계 | 하는 일 |
| --- | --- |
| 1 | DeX 설치 |
| 2 | XGEN에 연결 |
| 3 | 업무에 필요한 Agent 선택 |
| 4 | 필요한 실행 권한 연결 |
| 5 | 자연어로 업무 지시 |
| 6 | 결과물을 확인하고 이어서 작업 |

설치 화면과 각 단계의 자세한 설명은 실습 편에 화면과 함께 정리했습니다.

**→ [XGEN DeX 설치부터 첫 업무까지 — 여섯 단계](/blog/xgen-dex-install-guide)**

여기서는 각 단계가 왜 그렇게 설계되었는지만 짚어보겠습니다.

### Agent를 나누는 이유

모든 업무를 하나의 범용 AI Agent에게 맡기지는 않습니다.

기업에서는 업무마다 사용하는 데이터와 도구, 필요한 권한이 서로 다르기 때문입니다. 따라서 XGEN에서는 업무 목적에 맞는 Agent를 각각 구성하고, DeX에서는 상황에 맞는 Agent를 선택해 사용하는 방식을 권장합니다.

예를 들어 업무지원 Agent, 데이터 분석 Agent, 문서 작성 Agent, 개발지원 Agent, 부서별 전문 Agent를 하나의 DeX에서 필요에 따라 선택해 사용할 수 있습니다.

### 실행 환경을 연결하는 이유

Agent가 사용자의 PC에서 실제 업무를 수행하려면, 필요한 실행 환경에 접근할 수 있어야 합니다. 업무에 따라 **Local File / Storage, Browser, PowerShell, MCP, Skill, Application** 등을 활용합니다.

DeX는 이러한 실행 환경을 기본적으로 모두 열어두지 않습니다. 웹에서 관리되는 Agent가 사용자의 실제 업무환경으로 확장되는 지점이기 때문에, 필요한 실행 환경만 명시적으로 연결하도록 설계했습니다.

### Workspace가 중요한 이유

Agent가 만든 결과물은 다시 다음 업무의 시작점이 됩니다.

> "이 결과에서 전월 대비 변화가 큰 항목만 다시 정리해줘."

XGEN은 Agent를 단순한 LLM 호출 단위가 아니라 **LLM + Memory + Workspace + Tool + Execution Environment**가 결합된 업무 수행 단위로 확장하는 방향을 지향합니다. Agent가 작업한 파일과 업무 맥락을 이어받아 하나의 업무를 연속적으로 수행하려면, 이러한 업무 흐름을 이어가기 위한 Workspace가 필요합니다.

## 어떤 업무부터 적용하면 좋을까요?

DeX를 모든 업무에 적용할 필요는 없습니다.

가장 효과적인 시작점은 **사람이 여러 프로그램과 파일을 반복적으로 오가는 업무**입니다.

| 기존 업무 | DeX 활용 방식 |
| --- | --- |
| Excel 데이터 정리 | 파일 확인 → 데이터 분석 → 결과 파일 생성 |
| 정기 보고 업무 | 자료 취합 → 분석 → 보고자료 생성 |
| 회의 후속 업무 | 내용 정리 → 회의록 생성 → 후속 업무 정리 |
| 문서 검토 | 여러 파일 확인 → 비교 → 차이점 및 검토 결과 작성 |
| 웹 자료 조사 | 브라우저 검색 → 자료 확인 → 결과 정리 |
| 파일 반복 처리 | 폴더 확인 → 파일별 작업 → 지정 위치 저장 |
| 개발 업무 | 로컬 개발환경 및 Tool을 이용한 반복 작업 수행 |
| 사내 Agent 활용 | 업무별 Agent 선택 → 로컬 업무환경에서 실행 |

적용 대상을 선정할 때는 간단한 기준을 쓸 수 있습니다.

> **"이 업무를 수행하기 위해 직원이 하루에도 여러 번 파일을 열고, 복사하고, 검색하고, 다른 프로그램으로 옮기고 있는가?"**

그렇다면 DeX 도입 효과를 기대할 수 있는 업무입니다.

## 기존 업무 시스템을 대체하려는 것은 아닙니다

여기서 중요한 원칙이 하나 있습니다.

XGEN DeX가 Excel이나 PowerPoint, 브라우저, SharePoint 같은 기존 업무 도구를 새로 만드는 것은 아닙니다.

기업에는 이미 잘 사용하고 있는 업무 시스템과 SaaS, 애플리케이션이 있습니다.

DeX의 역할은 이를 대체하는 것이 아니라 **Agent가 기존 업무 도구를 더 쉽게 활용할 수 있도록 연결하는 것**입니다.

즉, 새로운 업무 도구를 하나 더 만드는 것이 아니라 **기존 업무환경에 AI Agent의 실행 능력을 더하는 것**에 가깝습니다.

---

## 서버와 로컬 자원을 함께 활용합니다

Enterprise Agent에서는 모든 업무를 서버에서 처리하는 것이 항상 효율적인 것은 아닙니다.

PC에 있는 파일과 애플리케이션을 활용하는 업무는 로컬 실행환경에서 처리하는 것이 더 효율적입니다.

반대로 기업의 공통 데이터나 중앙에서 관리해야 하는 AI 모델, Agent 자산 등은 서버에서 관리하는 것이 적합합니다.

XGEN DeX는 이러한 특성을 고려해 **서버의 Agent 자원과 사용자의 로컬 실행환경을 연결하는 구조**를 지향합니다.

이를 통해 기업은 중앙에서 Agent와 주요 자산을 관리하면서, 실제 실행이 필요한 업무는 사용자의 업무환경과 연결할 수 있습니다.

## Agent가 바탕화면에 상주합니다

업무용 도구는 창을 열어야 쓸 수 있습니다. 무언가 시키려면 앱을 찾아 띄우고, 대화창을 열고, 그다음에야 말을 겁니다. 그 몇 단계가 「그냥 내가 하지」로 돌아가게 만듭니다.

DeX는 Agent를 **화면 위에 떠 있는 아바타**로 둘 수 있습니다. 사진이나 Live2D·Spine 모델을 올려 모습을 정하고, 크기와 위치를 맞추면 창을 최소화해도 그 자리에 남습니다.

![아바타 설정 화면에서 기능을 켜자 선택한 아바타가 바탕화면 오른쪽에 떠 있는 모습](/connector/15-avatar-overlay.webp)

*아바타를 켜면 Agent가 바탕화면에 상주한다*

직접 올리지 않아도 됩니다. 「스토어」에는 이미 만들어진 캐릭터가 올라와 있어, 내려받아 바로 쓸 수 있습니다. 팀에서 쓰는 캐릭터를 함께 두면 Agent마다 다른 얼굴을 줄 수도 있습니다.

![아바타 스토어에 여러 캐릭터 카드가 나열되고 각 카드에 내려받기 버튼이 있는 화면](/connector/16-avatar-store.webp)

*스토어에서 캐릭터를 골라 내려받는다*

아바타는 단순한 시각적 요소가 아닙니다. Agent를 **찾아가는 대상이 아니라 옆에 있는 동료로** 두려는 것입니다. 서버에서 관리되는 Agent가 사용자의 업무환경에 실제로 자리 잡았다는 것을, 화면에서 가장 단순하게 보여주는 방식이기도 합니다.

## 기업용 DeX라면 통제가 함께 필요합니다

AI가 PC와 기업 데이터에 접근할 수 있게 되면 반드시 함께 고려해야 하는 것이 있습니다.

**보안과 거버넌스입니다.**

누가 어떤 Agent를 사용할 수 있는지, Agent가 어떤 데이터에 접근할 수 있는지, 어떤 Tool을 실행할 수 있는지, 어떤 작업을 수행했는지 기록할 수 있는지, 민감한 정보에 접근하려 할 때 이를 어떻게 감지하고 통제할 것인지가 중요합니다.

특히 금융·공공·대기업에서는 Agent의 편리함만큼 이러한 관리 체계가 중요합니다.

따라서 XGEN DeX가 지향하는 방향은

**"AI에게 내 PC를 맡긴다"**

가 아닙니다.

**"기업이 관리하는 Agent에게 허용된 업무환경과 도구를 연결한다"**

에 가깝습니다.

XGEN의 Agent 관리 및 AI 거버넌스 체계와 DeX가 함께 발전해야 하는 이유입니다.

## AI에게 질문하는 것에서, 업무를 맡기는 것으로

지금까지 기업의 생성형 AI는 주로 사람이 질문하고 AI가 답변하는 방식으로 사용되어 왔습니다.

하지만 Agentic AI에서는 한 단계가 더 필요합니다.

AI가 답변을 생성하는 것을 넘어 **필요한 도구를 사용하고 실제 업무 결과물을 만들어야 합니다.**

XGEN DeX는 XGEN의 Agent와 실제 업무환경 사이에 존재하는 이 마지막 간극을 연결합니다.

**XGEN에서 Agent를 만들고
→ 기업의 데이터와 시스템을 연결하고
→ 필요한 Tool과 Skill을 제공하고
→ DeX를 통해 실제 업무환경에서 실행합니다.**

결국 기업의 AI 활용 방식은

**Ask → Answer**

에서

**Request → Understand → Execute → Deliver**

로 확장됩니다.

XGEN DeX가 만들고자 하는 것은 또 하나의 AI 채팅 프로그램이 아닙니다.

> **기업이 구축한 AI Agent를 실제 업무환경으로 연결하는 실행 접점.**

그것이 XGEN DeX가 필요한 이유입니다.
