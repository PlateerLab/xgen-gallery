> 이 글은 [XGEN DeX — 기업 AI Agent를 실제 업무환경으로 연결하다](/blog/xgen-dex-desktop-connect)의 실습 편입니다. 앞선 글이 "왜 데스크톱까지 이어야 하는가"를 다뤘다면, 이 글은 그것을 직접 해봅니다.

AI에게 일을 시켜 본 사람은 대개 같은 지점에서 멈춥니다. 답은 잘 나오는데, 그 답을 실제 파일로 만들고 폴더에 넣는 일은 결국 사람이 합니다.

XGEN DeX는 그 마지막 구간을 잇습니다. 서버에 있는 Agent가 내 PC의 파일과 도구를 쓰도록 연결하는 데스크톱 접점입니다.

설치 파일은 GitHub 저장소에서 받습니다. 용량은 약 280MB이고, 화면은 Windows 기준입니다.

**→ [PlateerLab/xgen-connector](https://github.com/PlateerLab/xgen-connector)**

## 1. 설치하기

내려받은 `XGEN-Connector-Setup` 파일을 실행하면 Windows Defender SmartScreen이 「인식할 수 없는 앱」이라며 막습니다. 코드 서명 인증서가 아직 등록되지 않아 나타나는 화면으로, 설치 파일 자체의 문제는 아닙니다. 「추가 정보」를 누르면 게시자와 파일명이 표시되고 「실행」 버튼이 나타납니다.

![Microsoft Defender SmartScreen 이 인식할 수 없는 앱의 시작을 차단했다는 파란 대화상자](/connector/03-smartscreen-block.webp)

*사내 배포 시 이 화면 때문에 문의가 들어옵니다. 배포 안내에 미리 적어두는 편이 좋습니다*

설치 범위는 모든 사용자와 현재 사용자 중에서 고릅니다. 현재 사용자로 두면 관리자 권한이 필요 없어 사내 배포에서도 무난합니다.

![모든 사용자와 현재 사용자 전용 중에서 설치 범위를 고르는 화면](/connector/04-scope.webp)

*설치 옵션 선택*

설치 폴더는 기본값이 사용자 계정 아래의 AppData 경로이며, 약 970MB의 여유 공간이 필요합니다.

![설치 폴더 경로와 필요한 디스크 공간 971.6MB 가 표시된 화면](/connector/06-install-path.webp)

*설치 위치 선택*

이어지는 화면에서 데이터 폴더를 지정합니다. 그 아래에 Agent의 작업 폴더와 로컬 실행 구성요소가 만들어집니다 — `workspace`는 작업 동기화, `cloud`는 스토리지, `local-runtime`은 Agent가 이 PC에서 실행될 때 쓰는 런타임과 CLI입니다.

로컬 런타임과 파이썬 패키지가 복사되면서 시간이 걸립니다. 진행 막대가 끝나면 「마침」으로 닫고 DeX를 실행합니다.

![설치가 완료되어 XGen-Dex 실행하기 체크박스와 마침 버튼이 보이는 화면](/connector/08-complete.webp)

*설치 완료*

## 2. 서버 연결

처음 실행하면 접속할 XGEN 서버(게이트웨이) 주소를 묻습니다. 기업에서 운영 중인 XGEN 주소를 넣습니다.

사내 인증서를 쓰는 환경이라면 「사설 인증서 허용」을, 통합 인증을 쓴다면 「SSO 로그인 사용」을 함께 켭니다.

![XGEN 서버 주소 입력란과 사설 인증서 허용, SSO 로그인 사용 체크박스가 있는 서버 연결 화면](/connector/09-server.webp)

*접속할 XGEN 서버를 지정한다*

## 3. XGeny로 Agent 만들기

DeX는 Agent를 **실행하는** 쪽이고, Agent 자체는 XGEN에서 만듭니다. 캔버스에서 노드를 직접 잇는 방법도 있지만, XGeny에게 말로 시키는 편이 빠릅니다.

![XGEN 캔버스에 에이전트 XGeny 노드가 놓이고 AI 제공사와 모델을 고르는 세부 설정이 열린 화면](/connector/17-xgeny-node.webp)

*캔버스의 XGeny 노드*

대화창에 「플래티어 랩스 사이트에 블로그 아티클을 작성하는 에이전트를 만들어줘」처럼 하려는 일을 적으면, XGeny가 필요한 노드와 연결을 갖춘 워크플로우를 만들어 캔버스에 올립니다.

![XGEN 대화창에 블로그 아티클을 작성하는 에이전트를 만들어 달라고 요청한 화면](/connector/18-xgeny-prompt.webp)

*만들고 싶은 Agent를 말로 설명한다*

입력, 대화 기억, 웹 검색, 에이전트, 답변 출력이 이어진 워크플로우가 만들어집니다. 그대로 실행해 보면서 노드를 더하거나 설정을 바꿔 다듬은 뒤, 이름을 붙여 저장합니다.

![사용자 질문 입력, 멀티턴 DB, 통합 웹 검색, 에이전트 XGeny, AI 답변 출력 노드가 선으로 이어진 캔버스 화면](/connector/19-xgeny-flow.webp)

*XGeny가 만든 워크플로우*

## 4. 내 PC에 연결하고 작업 폴더 만들기

XGEN 서버에서 돌아가는 Agent가 이 PC의 파일을 읽고 쓰려면, 그 Agent와 이 컴퓨터를 서로 연결해 두어야 합니다. XGEN의 「지식관리 → 파일 클라우드 → 연결」에서 합니다.

DeX가 켜져 있으면 「연결된 PC」에 이 컴퓨터가 자동으로 나타납니다. 「+ 에이전트 연결」로 앞에서 만든 Agent를 고르면, XGEN 서버의 Agent와 사용자의 데스크톱이 이어집니다.

![에이전트 연결 대화상자에서 AI랩스 사이트 운영 Suan Agent 를 고르는 화면](/connector/21-connect-agent.webp)

*연결할 Agent 고르기*

![연결된 PC 와 연결된 에이전트가 각각 연결됨 상태로 표시된 화면](/connector/22-connected.webp)

*PC와 Agent가 모두 연결된 상태*

> 연결된 Agent는 내 클라우드 전체를 읽고 쓸 수 있습니다. 업무에 필요한 Agent만 연결하고, 쓰지 않을 때는 「일시중지」로 끊어 둡니다.

「보관함」에서 저장소를 만들면 클라우드 폴더가 생기고, 같은 이름의 폴더가 내 PC의 기본 작업 폴더 아래에 동기화됩니다. 이 폴더가 Agent와 사람이 파일을 주고받는 자리입니다.

![보관함에 동기화 표시가 붙은 저장소 카드가 하나 있는 화면](/connector/24-folder-list.webp)

*PC와 동기화되는 클라우드 폴더*

「작업 내역」에는 누가 언제 무엇을 했는지 남습니다. 아래는 폴더를 만든 `mkdir` 기록입니다.

![작업 내역에 mkdir 작업과 행위자, 시각이 표시된 화면](/connector/25-activity.webp)

*사람이 한 일과 Agent가 한 일이 같은 목록에 쌓인다*

## 5. 실행 권한 열기

Agent가 이 PC에서 무엇까지 할 수 있는지는 DeX의 「설정」에서 정합니다. 필요한 것만 열어 두는 것이 기본입니다.

「PC 컨트롤」은 셸과 파일 접근입니다. 기본 작업 폴더와 허용 폴더로 범위를 묶고, 삭제·전원·권한 상승 같은 명령은 첫 단어 기준으로 막을 수 있습니다.

![로컬 도구 접근 스위치와 기본 작업 폴더, 허용 폴더, 차단할 명령 설정이 있는 PC 컨트롤 탭](/connector/11-pc-control.webp)

*PC 컨트롤 — 셸·파일 접근 범위*

「MCP」는 내 PC에서 MCP 서버를 띄워 선택한 세션의 Agent가 그 도구를 쓰게 합니다. 「스토리지」는 클라우드를 드라이브처럼 붙이고, 연결된 Agent의 워크스페이스를 실제 폴더로 동기화합니다.

![로컬 MCP 사용 스위치와 등록된 MCP 서버 목록이 있는 MCP 탭](/connector/12-mcp.webp)

*MCP — 내 PC에서 띄우는 도구*

## 6. 업무 맡기기

여기까지 오면 앞에서 만든 Agent가 DeX 왼쪽 목록에 나타납니다. 고르면 바로 대화가 시작됩니다.

그전에 하나 더 있습니다. 「아바타 설정」에서 기능을 켜면 Agent가 **화면 위에 떠 있는 캐릭터**로 나타납니다. 사진(png/jpg)이나 Live2D·Spine 모델을 올려 쓰고, 휠로 크기를, 드래그로 위치를 정합니다.

![아바타 설정 화면에서 기능을 켜자 선택한 아바타가 바탕화면 오른쪽에 떠 있는 모습](/connector/15-avatar-overlay.webp)

*아바타를 켜면 Agent 가 바탕화면에 상주한다*

직접 만들 필요는 없습니다. 「스토어」에 이미 만들어진 캐릭터가 올라와 있어, 마음에 드는 것을 내려받아 바로 쓰면 됩니다.

![아바타 스토어에 여러 캐릭터 카드가 나열되고 각 카드에 내려받기 버튼이 있는 화면](/connector/16-avatar-store.webp)

*스토어에서 캐릭터를 골라 내려받는다*

창을 최소화해도 아바타는 남습니다. 매번 앱을 찾아 열지 않고, 옆자리 동료에게 말 걸듯 바로 일을 시킬 수 있습니다. 아래 대화 화면 오른쪽에 보이는 캐릭터입니다.

명령어가 아니라 결과물 단위로 맡깁니다. 아래는 「국내 온프레미스 B2B 에이전트 솔루션 혹은 플랫폼에 대해 최근 한달 내 가장 조회수가 높은 보도자료를 찾아서 정리해봐」라고 요청한 장면입니다.

Agent는 무엇을 할지 되짚어 확인한 뒤 웹 검색을 돌리고, 찾은 자료를 제목·URL·날짜·요약으로 정리해 돌려줍니다. 어떤 도구를 몇 번 썼는지는 「전체 로그 보기」에 남아, 결과만 볼지 과정까지 볼지 고를 수 있습니다.

![DeX 대화창에서 Agent 가 찾은 보도자료를 제목·URL·날짜·요약으로 정리해 답한 화면](/connector/28-agent-task.webp)

*맡긴 업무의 결과가 정리되어 돌아온다*

결과물은 4단계에서 만든 동기화 폴더에 그대로 떨어집니다. 탐색기 왼쪽에 Agent의 폴더가 붙고, 같은 내용이 로컬 경로에도 동기화됩니다.

![왼쪽 탐색기에 XgenCloud 와 AI랩스 사이트 운영 Suan Agent 폴더가 보이고, 오른쪽 스토리지 탭에 그 에이전트의 로컬 동기화 경로가 표시된 화면](/connector/27-synced-folder.webp)

*탐색기에 Agent의 폴더가 붙고, 로컬 경로로도 동기화된다*

여기까지 오면 XGEN에서 만든 Agent가 사용자의 데스크톱 환경과 연동되어, 로컬 파일과 애플리케이션을 활용해 실제 업무를 수행할 준비가 끝납니다.

## 운영하면서 알게 되는 것

**업무마다 Agent를 나눕니다.** 하나의 범용 Agent에 모두 맡기지 않습니다. 업무마다 쓰는 데이터와 도구, 열어야 할 권한이 달라서, 사이트 운영과 문서 정리를 같은 Agent에 맡기면 필요 없는 권한까지 함께 열리게 됩니다.

**쓰지 않을 때는 끊어 둡니다.** 연결된 Agent는 클라우드 전체를 읽고 씁니다. 「파일 클라우드 → 연결」에서 「일시중지」로 끊어 두면 연결 설정은 남고 접근만 멈춥니다.

**결과에서 이어갑니다.** Agent가 만든 결과물은 다음 업무의 시작점이 됩니다. 동기화 폴더에 그대로 남아 있으므로 「방금 만든 결과를 경영진이 보기 쉽게 요약해줘」처럼 맥락을 이어갈 수 있습니다.
